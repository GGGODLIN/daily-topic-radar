## Problem Statement

既有本機分析已能找使用者糾正、重複流程與同型錯誤。使用者希望在現有機制中補一個角度：從單次解題過程找出有結果支持、下次可能重用的做法，送進每日本機報告，由使用者決定是否採用，而不是自動生成技能。

## Solution

在既有 distill 中加入「單次解題經驗」候選類別，沿用週二發現、每日報告依既有條件呈現待辦的接線。候選說明問題、有效做法的結果證據、適用限制與建議補入的既有內容。先排除已覆蓋或已否決的同一提案；不另開分析入口，不自動修改正式資產。

## User Stories

1. 身為使用者，我希望在既有分析機制內增加單次解題經驗的角度，而不是另建一套系統。[user: "等於是在現有機制內加一個角度對吧？"]
2. 身為使用者，我希望候選進入每日本機報告，讓我決定是否採用。[user: "最終應該也是進入每日本機的報告讓我決定？"]
3. 身為使用者，我希望沿用週二挖掘、每日報告承接的頻率，並以有結果支持的新解法、已有或已否決提案、只有 AI 自述成功等情境驗收；使用者已確認前述頻率與驗收說明。[user: "可以"]
4. 身為使用者，我不希望候選在未告知與未批准的情況下變成可載入技能。[user: "但我不喜歡skill在我不知情的情況下自己長出來，因為skill是需要付出常駐成本的"]
5. 身為使用者，我選擇不列出證據不足的線索，也不為它們新增待辦；沒有合格候選時明確說沒有。若讀取失敗或資料缺失影響分析，只簡短揭露限制，不把未分析到當成確認沒有。[user: "a"]

## Implementation Decisions

- 修改既有 distill 的分析指令與對應測試，加入單次經驗類別；沿用目前每週二執行的註冊與每日待辦消費，不修改排程、報告主入口或狀態轉換機制。[evidence: 現行 local-analysis CHANNELS、distill 分析指令與本機分析三分架構；本輪已確認沿用頻率]
- 單次經驗不套用重複流程與同型錯誤的跨日門檻；原有分析類別的門檻與行為不變。從既有 session 線索定點回讀原始對話與工具結果，不新增全機掃描器或資料平台。[evidence: AutoHarness reflector 的單次 technique/fix/workaround 訊號與現行 distill 的 session 指紋及原始紀錄回查接縫]
- 候選以簡短敘述交代值得留下的做法、支撐結果的原始證據與建議補入位置，不要求固定五段式填空；影響判斷的情境或適用限制併入敘述。核對工具呼叫與對應結果，不能只憑 assistant 自述成功或無關命令正常退出判定有效。證據不足不列候選、不建立待辦，也不另列待確認線索；影響分析的資料限制只簡短揭露。[inferred]
- 提案前先用簡介定位，只定點讀與該候選最接近的既有內容正文及相關決策，不全量讀取技能庫；不能僅因簡介沒寫就認定是新內容。優先考慮本次實際用過且範圍相符的內容。已覆蓋、已採用或已否決的同一提案不再列新候選，既有待辦不重建；不更改原有待辦的提醒或狀態規則，也不自動重啟已否決項目。[evidence: 已批准的排除範圍、現有資產對照及 pending-actions 消費接縫]
- 候選只進普通分析報告，再交原有報告排檔與待辦流程處理。禁止本分析直接修改 skill、command、規則或專案文件；不自行改寫決策帳的狀態。原始紀錄視為資料，引用移除秘密與不必要個資。[user: "最終應該也是進入每日本機的報告讓我決定？"]

## Testing Decisions

- 在 distill 報告輸出層驗收，沿用現有 prompt 取得與報告交付接縫；不另設服務或資料庫。
- 用可控案例實際執行分析：有對應工具結果的新解法應成為有來源的候選；正文已有及已否決的同一提案不得冒充新發現；只有 assistant 自述成功或缺對應結果的案例不得列為候選或新增待辦；影響分析的資料限制只簡短說明。
- 同時檢查結果只形成報告，沒有修改正式技能或決策狀態。測試使用隔離資料，不向正式待辦寫入測試候選。
- 不為新段落另建依賴固定措辭的 prompt 字串測試；保留必要的 shell 語法檢查與既有報告契約回歸，這些檢查不取代上述實際輸出驗收。
- 回歸範圍優先選 distill 的最近測試及既有 workflow 報告契約；只有實際修改到其他層時才擴大，不為本次單一分析角度重跑全機檢查。

## Out of Scope

- 安裝或執行 AutoHarness plugin、promoter、自動生成或封存技能。
- 新增獨立 channel、排程、常駐服務、全域共用抽取平台或新的待辦狀態。
- 自動實作候選、重新開啟已否決提案、變更既有提醒頻率。
- 宣稱單次成功可普遍套用，或以候選數量證明改善效果。
- 順手改造其他分析類別、敏感資料處理系統或規則治理。

## Further Notes

此規格只落實已確認的候選發現與呈現，不代表使用者批准任何未來候選的內容修改。成功案例的適用性與實際收益仍需後續判斷。

ADR 條件檢查：新增分析角度與測試是可逆修改；排程、狀態與授權均沿用既有設計。沒有同時符合難以逆轉、缺脈絡會意外、具有實質取捨的新增決策，本次不建立 ADR。

實作驗證回寫：隔離合成案例中，有對應結果的新做法列為 D 線候選；正文已有、已否決、自述成功與缺結果的做法不列為新 D 線候選，無合格組明示沒有並揭露資料限制。原 A／B／C 的主要分析段落維持不變；原 B 線仍可能提出自己的漂移建議，不能把 D 線驗收外推為整個 distill 無誤報。此驗收替換了資料取得接縫，尚未實跑正式週二排程或每日報告消費，也沒有量測長期收益。詳見 [本地驗收](file:///Users/linhancheng/code/social-info/.scratch/single-session-lessons/acceptance/verification.md)。
