# Main scope 差額治理

## Problem Statement

使用者授權解決問題後，main 可能把自選方案需要的配套升格成必做需求。即使 worker 完全遵守派工要求，工作仍可能超出使用者預期。既有最小修改提醒曾出現在事故 session，不能假設增加文字即可改善行為。

## Solution

在既有 main 工作紀律中加入累積範圍差額檢查，並由既有實作流程引用。不新增 hook、審查 agent、授權收據或獨立 command。先試行，以真實行為觀察效果，不把規則存在或自報遵守當成功。

## User Stories

1. 使用者希望必要的小修正仍可自決，但新增能力、跨系統修改或為假設風險增加機制時先停止加碼，縮回或請使用者拍板。[user: "可以先往這個方向"]
2. 使用者希望 AI 的行動不超出授權，證據不足時收窄結論，而非為補證據自行擴大工作。[user: "這我覺得是程度問題。我可能會希望能講明白證據到哪scope就到哪，但不希望因為這樣擅自擴張scope，你能理解我的意思嗎"]
3. 使用者希望透過 trial 判斷 prompt 層治理是否有實際效果。[user: "行，設計很好，唯一的問題就是prompt層治理有多少用處對吧，那就看trial吧"]

## Implementation Decisions

- 單一規則定義放在既有派工與驗證工作紀律；既有 implement 共同執行步驟引用它，覆蓋 main 自做與 subagent 派工。不修改既有 review-spec、review-implement、ticket-yagni 的審查種類與授權語意。[user: "行，設計很好，唯一的問題就是prompt層治理有多少用處對吧，那就看trial吧"]
- 首次形成具體實作要求、修改派工內容／換方案／重派，以及接受會增加工作範圍的 review 建議前，對照最近明確批准的目標與邊界；累積未獲批准的改動不得用上一版 plan 洗成既有要求。未被新決策取代的既有約束仍有效。[inferred]
- 分開辨認目標要求與方案要求。選型產生實作約束不自動構成越權；新增能力、跨系統修改、假設風險機制或持續維護承諾才需要先縮回或帶取捨請拍板。不能以工具／檔案名稱、行數或檔案數直接定罪。[inferred]
- 有符合原目標與既有授權的較小方案時自行縮回；等效更簡單替換與必要局部修正不增加逐步確認。不存在安全且符合原目標的較小方案時，回報限制，不得藉縮小方案偷偷降低已批准驗收。[inferred]
- 方案被否決後重新考慮縮小或停止，不只換架構繼續；review 發現真缺陷不等於其建議修法自動獲授權。[inferred]
- 需要拍板時只呈現原授權、新增差額、取捨與較小替代。未回答時不執行新增部分；原範圍內不相依工作可繼續。拒絕後不得改名、換 worker 或改寫驗收條件繼續做。使用者明確批准後才更新範圍。[inferred]
- main 不得先把未批准要求塞入 ticket、測試或 worker 驗收，再以這些產物證明必要性。原始授權不清楚時讀取既有決策與對話；仍無法釐清且會改變範圍時交使用者確認。[inferred]
- 不要求每次讀檔或跑測試都檢查，不建立逐次表單或機械授權系統。prompt 契約不保證 main 能正確辨認或一定遵守。[inferred]
- 上線時登記既有 trial ledger 並建立 detail；review 日期按實際上線日加七天，不從設計討論日起算。不新增 cron、採樣 daemon 或獨立 telemetry。review 使用既有 session transcript；樣本不足依既有 trial 規則延一輪，不宣稱成功。[inferred]
- Trial 逐案記錄實際授權、main 派工或直接動作、是否先縮回／先問／先做、使用者糾正，以及不必要請示；規則載入與自報僅作輔助。觀察結果不作因果效果或全量發生率保證。[inferred]

## Testing Decisions

- 驗收 seam 是 main 在給定使用者原始授權與情境後的可見回覆、派工要求與實際工具動作；main 自做與派工兩路都覆蓋。使用者已在示例說明後接受設計，實際修改前由既有 skill-creator 流程落成行為驗證。
- 正向案例：本機 hook 最小啟用可自決；局部空資料修正與必要測試不增加請示；等效更簡單替換不改驗收。
- 邊界案例：本機目標延伸跨機部署時先縮回或詢問；多輪小幅加碼仍對照批准基準；review 建議新增狀態機時考慮較小替代；證據不足收窄結論而非擴測；無答覆／拒絕時沒有新增範圍的工具動作。
- 本次修改前短情境未重現失敗，無有效RED。使用者其後提出「也許直接上線看看行為有沒有改善比較快」，本次改採效果未知的自然trial：不追加短情境追求RED，不以RED／GREEN差異作上線前提；保留受影響的既有implement契約與必要靜態檢查。不以文字命中冒充行為改善；合成測試不混入自然trial樣本。此例外只適用本次修改，不改skill-creator的通用規則。
- 本 spec 不授權重演真實遠端 mutation 或擴建測試框架。

## Out of Scope

- 新 hook、command、review agent、permit／receipt／manifest 系統。
- 同 scope 的時間、token、行數或檔案數上限；此界線尚未拍板。
- 修改既有 review-spec、review-implement 或 ticket-yagni。
- 全機稽核、無關規則清理、跨機 rollout、Beads 結案。
- 將單一案例推算發生頻率，或保證 prompt 治理可以攔截所有越權。

## Further Notes

歷史案例是已授權目標下的 main 派工範圍膨脹；不能推定 subagent 完全無額外偏差，也不能據此宣稱未授權部署或生產事故。
