🆕 CC CLI release

anthropics/claude-code release watcher 顯示兩個新 tag：v2.1.245（2026-08-25T05:13:24Z）與 v2.1.246（2026-08-25T22:31:52Z），都比 baseline v2.1.243 新。依 changelog 的工作流關聯拆成四組：

  • Bash／permissions：v2.1.246 加入 Bash wildcard allow rule 的啟動警告，提醒 subcommand 前的 wildcard 也會匹配插入的 options；/permissions 增加 Auto mode 分頁。前者直接對應本機 permission gate 的可見性，後者讓權限狀態更容易在 CLI 內核對。
  • MCP：v2.1.246 修復 headless／remote sessions 中被 incoming message 中斷的 MCP tool call 錯誤回報；另修復空 schema 參數型別處理。這是本機掛多個 MCP server 時比單純「支援 MCP」更實際的穩定性訊號，仍需在本機 route 實測才算採用證據。
  • session／background：修復 background session 啟動問題，並加入 dynamic workflow 重啟提示與回合完成時間。它們改善的是長流程的可見性與續接邊界，不等於已取代 workflow-monitor 的 pause／resume 機制。
  • transcript／rendering：改善 fullscreen／transcript 效能與捲動；v2.1.245 另修復 glibc 2.44 Linux 發行版啟動 crash。v2.1.246 對本機最直接的判讀是降低長 transcript 與背景 session 的操作摩擦，非功能性能力跳升。

採用判斷：★★★★ 追蹤並升級。這兩版的直接價值在 permission 可見性、MCP 錯誤回報與 background session 穩定性；本機 claude --version 未實測，升級指令記為 claude update，不要把 release API 查到的 tag 寫成已安裝版本。

1. 企業 Agent 從模型能力走向工作上下文與治理 5 key URLs

MCP 企業認證、跨產品 memory、workspace admin 與企業資料索引，把身分、權限、上下文和可觀測工作流推到 Agent 產品核心；豆包工作與飛書整合則顯示辦公 Agent 的競爭焦點已從聊天介面轉向實際工作協作。Claude／Anthropic 的具體訊號集中在上方固定段。

  • Workspace admin 變成產品本體：OpenAI Admin plugin把 workspace usage、成員與權限、limits、admin requests 放進 ChatGPT Work／Codex 的操作面，焦點不是再加一個聊天入口，而是治理工作流。
  • Agent 需要自己的 web index：Keenable以 2,600 萬美元 seed round 退出 stealth，主張建立給 AI agents 使用的大型 web search index；索引層開始被視為 agent 基礎設施，而非單純搜尋 UI。
  • 辦公 Agent 競爭移到上下文：豆包工作與飛書整合的報導把身分、訊息、文件、會議與權限放進同一工作上下文，直接對應企業 Agent 的可用性門檻。
  • 產品與組織一起重排：字節將 AI 產品能力向豆包集中，把「自主拆任務、調工具、做文件／表格／PPT」和飛書企業上下文綁在一起，顯示辦公 Agent 不再只比較模型回答品質。
  • 同一方向的實測敘事：愛范兒實測以「懂人、懂專案、懂上下文、懂工作流」描述豆包工作接入飛書後的體驗；這是媒體實測敘事，不等於獨立 benchmark。

對我的意義：★★★ 本機多 MCP、hook 與 workflow 的價值本來就不在「模型會不會回答」，而在權限、上下文與續接能不能被治理。這條軸支持繼續把身份與觸發交給機制、把決策留給人；它沒有提供要把本機流程改成某一家辦公 Agent 的理由。
